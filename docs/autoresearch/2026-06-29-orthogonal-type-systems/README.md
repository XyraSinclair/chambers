## Current recommendation

Implement a typed run-ledger and environment-receipt sidecar around the existing Python Chamber before building a marketplace, agent registry, container fleet, or matching network. The core spine is:

`Principal -> Chamber -> Scope -> Grant -> Transform -> Run -> Artifact -> Review -> Release -> ReceiptPayload -> LedgerEntry`.

Everything else should attach as an orthogonal module only when it has independent lifecycle pressure: observable egress budgets, environment receipts, attention cards, accepted deltas, reuse edges, settlement records, incidents, or bilateral release.
